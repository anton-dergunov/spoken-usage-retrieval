# Implementation notes for Plan 09

Working implementation handoff for [`09-audio-and-caption-reliability.md`](./09-audio-and-caption-reliability.md). This file records repository-specific findings and intended changes only; it does not repeat the task description.

Implemented on 2026-09-07: the first dependency-free cache-identity slice now exists in `src/speech_retrieval/audio.py` and `src/speech_retrieval/identity.py`. `AudioClipRange.from_seconds()` validates finite ordered ranges and nonnegative padding, requires requested values to have unambiguous millisecond precision, clamps padded ranges to the source duration, and retains requested and effective millisecond bounds separately. Its cache key includes the raw source SHA-256, requested range, padding, effective range, and the named `pcm-s16le-mono-16000-v1` preparation contract. `tests/test_audio.py` covers clamping, invalid ranges/checksums, every material key input, and a fixed identity vector. The full pytest suite passed with four optional skips; full Ruff check/format and mypy also passed. This slice does not yet locate media, invoke ffmpeg, write manifests, or expose a public package-root helper.

Implemented next on 2026-09-07: `probe_audio()` and the frozen `AudioProbe` record now provide the local media-inspection primitive in `src/speech_retrieval/audio.py`. The helper invokes ffprobe with a narrow JSON field selection through an injectable runner, requires a nonempty regular non-symlink file with exactly one audio stream and no video stream, validates positive duration/sample rate/channel count, captures format/codec and optional bitrate, and streams the file through SHA-256. Tests exercise valid and malformed injected probe responses and use stdlib `wave` to verify a real one-second mono 16 kHz PCM file when ffprobe is installed. The focused audio suite has 27 passing cases. The full pytest suite passed with four optional skips, and full Ruff check/format and mypy passed. Acquisition still needs to compare probe data with provider/manifest expectations, record ffprobe version, and publish only after atomic staging; this helper deliberately does not write cache state.

Implemented next on 2026-09-07: `validate_prepared_clip()` now enforces the post-conversion clip contract against an `AudioProbe`: WAV container, signed 16-bit PCM, mono, 16 kHz, and duration within a configurable integer-millisecond tolerance of the effective clamped range. Focused tests cover the valid contract and each mismatch independently; all 33 focused audio tests pass. The full pytest suite passed with four optional skips, and full Ruff check/format and mypy passed. This remains a pure validation seam; invoking ffmpeg and publishing or caching the validated artifact are still separate future steps.

Implemented next on 2026-09-07: `prepared_clip_paths()` and `PreparedClipPaths` now centralize the planned derived layout at `data/derived/audio/clips/<language>/<video_key>/<clip_key>/`, including fixed `clip.wav` and `manifest.json` paths. Language tags are canonicalized and both stable IDs are shape-checked before they become path components, so callers cannot supply traversal fragments. Unit tests for the layout and unsafe components were added but, at the user's request for this increment, were deliberately not run or otherwise validated.

Implemented next on 2026-09-07: `raw_audio_paths()` and `RawAudioPaths` now resolve the corresponding per-video raw-audio directory and its independent `audio/manifest.json` without creating anything on disk. The helper canonicalizes the language and requires a stable video ID; a focused layout test was added. As requested, validation was not run for this increment.

Implemented next on 2026-09-07: `RawAudioPaths.source()` now derives the immutable `source.<ext>` payload location while accepting only short lowercase alphanumeric media extensions. This keeps provider-supplied extension text from becoming an arbitrary path and completes the raw path descriptor without choosing a provider format. Focused valid/unsafe-extension tests were added; validation was not run, as requested.

Initial repository shape: this is a Python 3.12+ `src/` package with an `argparse` CLI, Pydantic contracts, dataclass settings, `yt-dlp`-based subtitle acquisition, pytest tests, and experiment directories that keep executable scripts, versioned configurations/schemas, results, and narrative reports together. Audio should extend those conventions rather than become a separate application.

Investigation order: trace acquisition/cache ownership and metadata first; then settings/CLI/status; caption provenance and segment identity; existing experiment/report formats; Plan 11/12 integration boundaries; finally dependencies and test seams. Findings below should turn into an implementation sequence once those paths are understood.

The current acquisition implementation is concentrated in `src/speech_retrieval/acquisition.py`. `acquire()` round-robins enabled channels, calls `_download_one()`, and writes `data/reports/acquisition-<language>.json`; `_download_one()` selects the canonical caption, saves authored secondary tracks, and owns `data/raw/corpora/<language>/<video_key>/manifest.json`. Track payloads live below the video directory as `<track_id>/metadata.json` plus `subtitles.raw.json3`. `_download_track()` stages into a temporary directory under the language raw root, validates nonempty JSON3 events, canonicalizes the JSON bytes, hashes them, and atomically renames the directory. Audio acquisition should copy this staging/validation/rename pattern rather than write a final media path directly.

Do not make optional audio another entry in the existing `tracks` array. `_cached_manifest()` currently requires every track status to be `downloaded` or `cached`, validates every track directory as a caption cache, and uses `complete` to describe caption-track enumeration. Putting audio there would couple caption usability/indexing to optional media availability and would break those assumptions. Prefer a sibling `media` object in the per-video manifest (or a separately versioned `audio-manifest.json` under the same video directory) whose readiness/failure is independently validated. If the shared manifest is extended, preserve backwards compatibility for manifests with no `media`, bump its schema only if readers cannot treat the field as optional, and keep caption `complete` semantics unchanged.

`src/speech_retrieval/identity.py` provides stable SHA-256-derived `video_key`, `track_id`, `segment_id`, and now `clip_id`. The implemented `AudioClipRange.cache_key()` supplies the raw source content SHA-256, requested/effective millisecond bounds, padding, and preparation version instead of embedding filename rules in callers. A separate raw-audio identity is probably unnecessary while each video has only one selected representation; if that changes, derive it from the stable video key plus acquisition/schema version. The named output contract in `AUDIO_PREPARATION_VERSION` prevents a future conversion change from reusing old WAV files under the same key.

The existing `CACHE_SCHEMA_VERSION` and `REPORT_SCHEMA_VERSION` are global integers used by captions. Avoid silently changing caption validity just to add media. Introduce explicit media-manifest/audio-preparation/feature/experiment schema or version constants, ideally near the component that owns each schema; only bump the global cache schema if a migration of existing caption metadata is actually required.

The yt-dlp runner currently returns stdout only, has a hard-coded 180-second timeout, and turns only the last stderr line into `AcquisitionError`. Audio needs more structured execution metadata and longer/configurable timeouts. Either generalize the runner contract in a backward-compatible way or add a separate injectable media runner. Preserve command injection in unit tests. Record the actual yt-dlp version (obtainable once per run via package metadata or `yt_dlp.version.__version__`), selected provider `format_id`, extension/container and codecs from provider metadata, rather than only the requested format selector.

Raw media should remain co-located with the stable video cache so caption metadata supplies provider/video/channel/language context without reconstructing provider directory rules. A concrete low-surprise layout is `data/raw/corpora/<language>/<video_key>/audio/source.<ext>` plus `audio/metadata.json`, while derived clips belong outside `raw`, for example `data/derived/audio/clips/<language>/<video_key>/<clip_key>/clip.wav` and `manifest.json`. Expose path resolution through library functions; experiment scripts and CLI code must not assemble this layout themselves.

`Settings` in `src/speech_retrieval/settings.py` is a frozen dataclass loaded from `SPEECH_RETRIEVAL_*` environment variables by an explicit converter map. New persistent controls therefore need both fields and converter entries plus validation. The minimum general setting is `with_audio: bool = False`; keeping the default false is what protects the subtitle-only quick start. Retry count/backoff and executable paths can be function/config parameters for the experiment unless there is a demonstrated need for long-lived service settings. If `ffmpeg`/`ffprobe` executable settings are added, validate nonblank strings but do not require the tools merely to construct default settings.

`Indexer.update_once()` in `src/speech_retrieval/service.py` is the production acquisition caller. It builds keyword arguments for `acquire()` from settings and then always rebuilds the index. Thread `with_audio` through this call without changing the `UpdateSummary.downloaded/cached` meanings, which currently count successfully acquired videos based on caption status. Add separate audio counts if the public update contract needs them; never count an audio-only retry as a newly downloaded caption video. Audio failure on a video with valid captions should be reported diagnostically but should not prevent the subtitle index from rebuilding. Whether it makes the overall update unsuccessful should be explicit; recommended semantics are that a user-requested `--with-audio` run reports partial failure/nonzero status while preserving and indexing the caption success.

CLI wiring is in `_parser()` and `_settings()` in `src/speech_retrieval/cli.py`. Add `--with-audio` to `update` using `argparse.BooleanOptionalAction` with default `None`, include `with_audio` in `_settings()`'s allowlist, and let the environment/default apply when the flag is absent. The compatibility `download_subtitles_main()` should remain subtitle-only unless its public purpose is deliberately renamed; its current test asserts the exact `acquire()` arguments and is a useful regression guard for the default. Top-level help is also snapshot-like tested in `tests/test_cli.py`.

The existing `status` command simply returns `Corpus.status()` from the SQLite index. Audio is deliberately not indexed, so audio counts cannot be reliably implemented only inside that SQL-backed method. Add a small media-cache scanner/storage-summary library and merge its result at the CLI/service-contract boundary, or extend `CorpusStatus` with an independently computed injected section. Keep readiness determined by the index: missing audio must not make `ready` false. A useful JSON shape is `audio: {enabled, ready, missing, failed, raw_bytes, derived_bytes}`; define explicit count denominators (for example, caption-cached videos versus all manifests) and use the same summary implementation for status and storage reporting.

`doctor` currently checks yt-dlp unconditionally because it is a base dependency. ffmpeg/ffprobe should be checked only as an optional capability: warning when audio is disabled, error (or a clearly actionable failed audio check) when an audio command is requested. Use `shutil.which`/a short `-version` probe rather than importing a Python wrapper. Capture the resolved executable and version in clip provenance.

The project ignores all of `data/` in `.gitignore`. Therefore raw downloads, full normalized audio, clips, ASR output, and local review working files can safely live there, while the versioned experiment config/schema/script and a scrubbed report belong under a new checked-in `experiments/audio-caption-reliability/` directory. The report must say explicitly which artifacts are intentionally ignored and give commands to regenerate them.

Segment timing already supplies the natural clip requests. `src/speech_retrieval/captions.py` emits stable `Segment` objects with caption span `start/end` and playback `clip_start/clip_end`; the latter currently applies 0.35 seconds before and 0.65 seconds after and clamps only the end to known video duration. The experiment configuration should freeze segment IDs and requested ranges, but call the common clip preparer with those existing `clip_start/clip_end` values and record its effective clamped range. Do not add a second implicit padding layer: pass `padding=0` for already padded segment ranges, or deliberately configure extra experiment padding and make that explicit in the cache key/config.

Automatic and manual timing have materially different meanings in current code. `automatic_units()` uses per-token-ish `tOffsetMs`, caps an estimated unit end at 0.4 seconds or the next start, and retains fine-grained `TimedTextSegment` entries. Manual captions use cue start/duration but `_segment_from_units()` intentionally collapses their character timing to one full-segment range. A WER/CER disagreement can therefore reflect transcription, caption segmentation, or an audio window that excludes speech because cue timing is poor. Preserve fields that let analysis separate these: caption kind, boundary reason/confidence, requested and effective audio range, ASR word/segment timestamps, and qualitative `boundary_problem`/`missing_speech`/`extra_speech` tags.

The current `quality_score` is not observed transcript reliability: it is a deterministic mix of boundary confidence, duration, token count, and a manual-caption prior (manual gets 1.0, automatic 0.65). Do not use it as a caption-quality label or leak it into sampling conclusions. It may be retained as a descriptive covariate so the experiment can test whether the prior is justified.

Index builds select only each video's canonical source track from `manifest.json`, validate its caption SHA-256, write the chosen segments to `data/derived/corpora/<language>/segments.jsonl`, and store the same segment/track/video fields in SQLite. Secondary authored tracks are cached but not indexed. Sampling both authored and automatic captions cannot rely on the current index alone when the canonical track is nearly always authored when available. The benchmark builder must either (a) construct segments directly from selected raw track metadata/JSON3 with `segment_payload()`, or (b) intentionally sample different videos whose canonical sources supply both provenances. Option (a) enables paired same-video comparisons but requires declaring that noncanonical tracks are experimental inputs and preserving their distinct `track_id`/caption language.

For canonical indexed samples, `data/derived/corpora/<language>/segments.jsonl` is the easiest deterministic inventory and stable segment IDs link back to source track/video. For secondary-track samples, generate a versioned sample inventory without modifying the production index. Never resample silently when media is missing: config rows should remain fixed and the results should record `missing_audio`, `download_failed`, `clip_failed`, or `asr_failed` for the same row.

The existing public `Clip` lookup is metadata for YouTube playback, not a local audio-file response. Plan 09 does not need to change `/api/v1/clips/{segment_id}` or serve cached WAV files. Its clip-preparation helper is a library/experiment interface that Plan 10 can later call; keeping local media out of the current API also avoids broadening the media-distribution/legal surface.

Plan 10 explicitly consumes a prepared 16 kHz mono clip and its provenance, so define a narrow return type now (for example a frozen dataclass or Pydantic model with `path`, video/source checksum, requested/effective range, padding, duration, sample rate, channels, sample format, preparation version, ffmpeg version, and creation time). Plan 12 consumes values by stable segment ID and feature version, not file paths. Feature outputs should therefore be a separate per-segment record keyed by `segment_id` and clip checksum/cache key; avoid burying feature values only inside clip manifests.

Experiment precedent is strong but should be tightened for this task. Existing scripts under `experiments/` keep committed challenge/config/schema files near code, put heavyweight/raw outputs under `data/experiments/<experiment>/`, atomically rewrite a partial report after each attempt, and retain provider raw output, validated representation, validation errors, latency, usage, and metadata. Follow the same checkpoint-after-each-item behavior for long audio/ASR runs so interruption loses at most the current example. Unlike some older experiment scripts, separate immutable configuration/sample snapshot from replaceable run outputs and include an explicit run ID plus timestamps/chronology.

Suggested checked-in experiment files are `experiments/audio-caption-reliability/README.md`, `config-v1.json`, `config-schema-v1.json`, `result-schema-v1.json`, and a small runner/build script (one script with `sample`, `prepare`, `transcribe`, `score`, `features`, `report`, and `preflight` subcommands is consistent with the morphology experiment). Local outputs should live at `data/experiments/audio-caption-reliability/<run-id>/` with `sample.jsonl`, `clips.jsonl`, `asr.jsonl`, `scored.jsonl`, `features.jsonl`, and `run.json`. Use atomic snapshot writes or append + fsync with duplicate-key rejection; reruns should skip only rows whose complete provenance/cache key matches.

The fixed config should contain the decision/hypothesis, acceptance evidence sought (not a universal WER cutoff), seed and deterministic selection algorithm, requested counts per stratum, exact selected segment/track/video IDs or a checksum-addressed sample snapshot, source languages, channel IDs, caption provenance, speech-style tags, acoustic-condition tags and how assigned, range/padding/preparation version, ASR provider/model/revision/device/decoding settings, normalization version/config, scoring unit choice, feature versions/settings, and manual rubric version. The run manifest adds code/package versions, input checksums, actual start/end chronology, host/device summary, runtime totals, failures and artifact checksums.

The repository-level experiment-report instructions in `AGENTS.md` are directly applicable and should be referenced during implementation rather than copied into the report. In particular, the final README/report needs denominators and distributions, representative success/borderline/failure cases with intermediate normalized/aligned output, exact manual-review evidence, artifact locations/reproduction commands, and limitations. `experiments/index.md` should gain the new dated row only once evidence exists; do not advertise a planned or empty experiment as complete.

The local cache observed during planning is useful for feasibility but is not itself a frozen benchmark. There are ten current per-video manifests, with seven automatic Spanish canonical tracks and three authored Spanish canonical tracks across four enabled channels. Those manifests have exactly ten Spanish tracks total; the other thirteen secondary tracks are authored translations in other languages, so they must not be miscounted as authored Spanish evidence. The current index reports thirteen videos/5,213 segments (ten automatic, three manual), meaning three indexed videos come from the legacy pre-manifest cache. Sampling code should either migrate/represent legacy entries explicitly or restrict version 1 to validated current manifests and state that denominator. Do not hard-code these planning-time counts because acquisition state can change.

The enabled Spanish catalogue covers learner/street interviews, clear explanations, travel/street interaction, and multi-speaker streaming. This can support an initial provenance/channel/style matrix, but three authored videos is too small for a broad source-class claim. A sensible v1 design is a balanced segment sample nested within the available videos (cap segments per video to prevent one long video dominating), followed by reporting uncertainty and video-level as well as segment-level distributions. Expand acquisition or enable a deliberately selected channel only if the preflight shows a missing stratum; never alter `config/channels/es.json` merely to make the benchmark look balanced.

“Obvious acoustic conditions” are not currently metadata fields and the channel-level `speech_style` arrays are broad, multi-valued catalogue descriptors. Use a two-stage freeze: deterministic candidate sampling by language/channel/provenance/style, then a documented listening pass that assigns a small controlled acoustic vocabulary (for example clean single speaker, background music/noise, overlapping speakers, distant/reverberant, fast speech) before final within-stratum selection. Record both assigned tags and reviewer/rubric version. Do not infer clip-level acoustics solely from channel tags or from the very VAD/SQUIM features under evaluation.

Sampling should use stable hash ordering over a canonical string such as `<seed>\0<segment_id>` instead of relying on Python iteration order. Enforce uniqueness, a per-video cap, minimum/maximum clip duration, nonempty text, valid source cache, and requested stratum quotas. Emit candidate and selected counts for every filtering step so an absent stratum is visible. If segments from the same video are close or overlapping, reject/cluster them before selection to avoid near-duplicate audio and correlated errors.

For provider media, keep the downloaded audio-only representation exactly as acquired; do not use yt-dlp `--extract-audio`, because that invokes ffmpeg and turns the supposed immutable input into a transcode. Inspect the formats returned by the existing metadata call, retain only real audio-only candidates (`vcodec == "none"`, usable audio codec, not DRM), and choose with a documented versioned policy. yt-dlp's own documentation warns that `worstaudio` is not equivalent to smallest file and recommends size-oriented sorting. A good policy is the smallest known/estimated file among candidates meeting an explicit speech-quality floor, with a deterministic quality fallback when sizes are unknown. Record every selector constraint and the chosen `format_id`, codec, container, bitrate, sample rate, channel count, advertised size and actual size. Source: <https://github.com/yt-dlp/yt-dlp#format-selection>.

Invoke the exact chosen `format_id` with `--no-playlist`, `--no-part` only if staging already guarantees incomplete files cannot escape, `--no-overwrites`, an output template inside a fresh temp directory, and explicit bounded retry settings. yt-dlp supports separate `--retries`, `--fragment-retries`, `--file-access-retries`, and exponential/linear `--retry-sleep`; set finite values in code/config instead of inheriting changing defaults. Source: <https://github.com/yt-dlp/yt-dlp#download-options>. Require exactly one produced media file and reject any file containing a video stream, rather than guessing the final extension.

The implemented `probe_audio()` now covers the common ffprobe JSON parsing, regular/nonempty file check, one-audio/no-video rule, positive duration/sample metadata, actual byte count, and streaming SHA-256 needed for both raw sources and derived clips. ffprobe documents these machine-readable sections at <https://ffmpeg.org/ffprobe.html>. Raw readiness still needs a manifest-level validator that compares this record with provider duration and stored checksum/fields. Only atomically rename the staged audio directory after that validation and metadata write succeed.

A separate mutable `audio/manifest.json` is preferable to editing the caption manifest because it can exist in `failed` state without any raw payload, transition to `ready` after retry, and retain bounded attempt diagnostics while the successfully acquired media file remains immutable. Suggested status vocabulary: `ready`, `failed`, and absence = `missing`; do not persist a `downloading` state unless crash recovery uses it. Each attempt should record timestamp, stage (`selection|download|probe|validation`), retryability/exhaustion, error code and sanitized message. Avoid persisting signed provider URLs, cookies, command lines containing credentials, or unbounded stderr.

Clip preparation can use an ffmpeg subprocess without a Python audio library. Clamp `requested_start - padding` to zero and `requested_end + padding` to probed source duration, reject non-finite/negative/reversed inputs, and derive a temporary WAV with accurate post-input seeking plus `-vn -ac 1 -ar 16000 -c:a pcm_s16le`. Explicit `-nostdin`, overwrite of only the fresh temp target, and quiet/error-only logs make it safe for service use. Probe the completed WAV and require codec `pcm_s16le`, one channel, 16,000 Hz, nonzero frames, and duration within a documented tolerance of the effective range before atomic publication. Store the output SHA-256 as well as the source checksum; Plan 10 can then key alignment to the actual bytes.

The clip manifest should distinguish `requested_start/end`, `padding_before/after`, `effective_start/end`, and `duration`. This handles source-boundary clamping without making equivalent requests ambiguous. Decide and test a canonical numeric precision (existing segment times are milliseconds, so integer milliseconds are a good cache-key representation) and reject rather than silently round meaningful sub-millisecond inputs. Serialize the canonical cache-key payload and hash it through a new identity helper.

The current environment happens to have ffmpeg/ffprobe 9.0.1, but this is not a repository guarantee and is not baked into code or tests. The implemented probe tests generate a WAV fixture with stdlib `wave`, inject probe output for deterministic edge cases, and skip their small real-ffprobe integration when the binary is absent. A future ffmpeg conversion integration and the network smoke test remain separate and opt-in as appropriate.

Keep the core package light. Audio acquisition and ffmpeg clip preparation need no new Python runtime dependency because yt-dlp is already a base dependency and ffmpeg is external. Add a dedicated optional extra such as `audio-experiments` for ASR/scoring/VAD/SQUIM instead of placing large ML dependencies in the existing `experiments` extra, which currently contains only SacreBLEU. The lock already contains PyTorch transitively for the optional Stanza extra, but that does not make TorchAudio, model weights, CTranslate2, or Silero available.

Use an injected `Transcriber` protocol so experiment I/O and tests do not import a heavyweight backend. Faster-Whisper is a pragmatic first adapter because it supports `large-v3`, explicit device/compute type, segment and word timestamps, and exposes relevant diagnostic fields; loading a model by name downloads a CTranslate2 checkpoint, so preflight must distinguish installed package, available local weights, and network-required preparation. Its output iterator is lazy, so runtime/error recording must cover materializing all segments, not just calling `transcribe()`. Official usage and timestamp details: <https://github.com/SYSTRAN/faster-whisper#usage>.

Freeze ASR settings rather than relying on backend defaults: exact model identifier and resolved Hub revision/checksum, package and CTranslate2 versions, `language="es"` (to avoid making language detection part of caption agreement), task `transcribe`, beam size, temperature/fallback policy, best-of/patience where applicable, condition-on-previous-text, VAD filtering, word timestamps, device, compute type, CPU threads/workers, and batch mode/size. Recommended initial settings for independent short clips are no caption-derived prompt, no VAD filter, no conditioning on a previous clip, explicit Spanish, and word timestamps enabled. The reference run must not use the tested caption as an initial prompt because that would bias agreement upward. Faster-Whisper's defaults differ from OpenAI Whisper (notably documented beam-size differences), so call this a Whisper `large-v3`-class reference and report the exact implementation rather than implying backend equivalence.

Each ASR result row should retain original backend segment/word output (text, starts/ends, probabilities/diagnostics when exposed), concatenated readable hypothesis, detected language/probability if returned, model provenance, clip key/checksum, wall-clock runtime, and structured failure. Keep provider output and validated representation separately, matching the repository's structured-generation experiment practice. Model load time and per-item inference time should be distinct; include total attempted/completed/failed counts and latency distribution.

Treat ASR as the declared comparison reference, not human truth. In scoring, orient WER/CER explicitly as `reference = normalized ASR`, `hypothesis = normalized caption`, so the denominator is ASR tokens/characters. Label the automatic metric `caption_asr_disagreement`, and only call something a confirmed caption error after listening/manual adjudication. Store substitutions, deletions, insertions, hits, reference length, hypothesis length, edit chunks/alignment, raw WER/CER (which may exceed 1), and a separately named bounded agreement feature if Plan 12 needs `[0,1]` (for example `max(0, 1-error_rate)`). Never discard the unbounded diagnostic metric.

Add a dedicated versioned scoring normalizer rather than reusing `src/speech_retrieval/text.py::normalize_token`, which deliberately strips accents for retrieval. A Spanish v1 normalizer should use Unicode NFC, case folding, normalized apostrophes, punctuation-to-space, and whitespace collapse while preserving diacritics; tokenize into auditable words and retain both original and normalized strings. Consider an accent-folded score only as a named sensitivity analysis. Do not silently equate digits and spoken number words or remove filler words: those differences may be exactly what the benchmark needs to expose.

For languages selected as character-scored, define whether spaces and punctuation are removed and whether script conversion is applied, then version that behavior per language. A second language belongs only when it tests a stated hypothesis; do not add Chinese/Japanese simply to exercise CER. The OpenAI Whisper documentation itself reports language-dependent WER/CER and notes special normalization choices for some scripts, reinforcing that metric selection/normalization cannot be universal: <https://github.com/openai/whisper#available-models-and-languages>.

JiWER is an appropriate optional scorer because `process_words`/`process_characters` expose alignment and counts and version 4 defines empty-reference behavior. Pin and record its version and pass already normalized token/character sequences so its default transforms cannot drift under the experiment. It is Apache-2.0. Source: <https://github.com/jitsi/jiwer>. Unit cases must assert exact `S/D/I/H` counts, not only final rates, for equality, insertion, deletion, substitution, empty/empty, empty/nonempty, accents, apostrophes, punctuation, and configured CJK spacing.

Use one generic feature result envelope for every optional acoustic helper: `segment_id`, feature name/version, status (`complete|unavailable|failed`), numeric value(s) and units, clip key/checksum, input provenance, implementation/model/settings provenance, runtime, and structured error. Missing dependencies/media produce `unavailable`; inference/validation exceptions produce `failed`; neither becomes numeric zero. This is the stable handoff Plan 12 needs.

Caption-to-ASR agreement should reuse the scorer output and name both its metric family (`wer` or `cer`) and normalization version. Speaking rate needs an explicit numerator and denominator: record caption-token and ASR-token rates separately, preferably over VAD speech seconds; also record clip-duration rates for diagnosis. Do not compare token rates across languages as if their tokenization were equivalent. If syllable rate is added for Spanish, its syllabifier and version need independent validation rather than a hidden heuristic.

For Silero VAD, run on the prepared 16 kHz mono waveform, retain the returned speech intervals, merge overlaps before summing, and define `speech_ratio = union_speech_seconds / effective_clip_duration`. Record model/version/backend (Torch or ONNX), threshold, minimum speech/silence durations and speech padding. The official model supports 8/16 kHz and recommends tuning these parameters; do not treat defaults as validated on this corpus. Source: <https://github.com/snakers4/silero-vad>. Review false positives from music/noise and false negatives for quiet/overlapped speech, not just the scalar ratio.

SQUIM needs two distinct adapters/results. `SQUIM_OBJECTIVE` produces reference-free estimates of STOI, PESQ, and SI-SDR. `SQUIM_SUBJECTIVE` produces MOS but still requires a non-matching reference waveform; therefore “reference-free MOS” does not mean “no second input.” Choose a fixed, appropriately licensed non-matching speech reference, keep it under ignored experiment data unless redistribution is allowed, and record its source/license/checksum and preprocessing. The official tutorial shows this interface: <https://github.com/pytorch/audio/blob/main/examples/tutorials/squim_tutorial.py>. If no defensible reference is available, mark MOS unavailable rather than inventing one.

TorchAudio entered maintenance mode in 2.9 and moved I/O toward TorchCodec, so isolate SQUIM behind a narrow adapter and do not use its changing load/save APIs for the core clip pipeline. Source: <https://docs.pytorch.org/audio/main/torchaudio>. Pin compatible Torch/TorchAudio versions in the experiment extra and record pretrained bundle/weight identity. The sample review must assess each output (predicted STOI, PESQ, SI-SDR, MOS) independently against human `hard_to_follow`/quality judgments; a useful-looking correlation from one metric does not promote the others.

The manual review must explicitly adjudicate the ASR baseline rather than assume every disagreement is a caption error. A compact record can include `caption_verdict: correct|acceptable|incorrect|uncertain`, `reference_assessment: equivalent|caption_better|asr_better|both_wrong|uncertain`, multi-select tags for meaning change, omitted speech, extra speech, name/entity error, disfluency difference, punctuation-only difference, start cut, end cut, overlap, noise/music, and unclear speech, plus reviewer ID/pseudonym, rubric version, timestamp and note. Include a short corrected transcript only where needed to explain a representative discrepancy; keep it local if redistribution is questionable.

Review either the entire manageable fixed sample or predeclare a review subset before examining results. A defensible cheaper subset is all failed/extreme disagreements plus stable hash samples from low and middle disagreement bins in every source stratum; report exact reviewed/total denominators and do not extrapolate unreviewed automatic metrics as confirmed errors. Duplicate-review a small stratified subset if possible and report agreement/disagreements. Plan 11 is still only a plan in this checkout, so there is no implemented judgment schema to reuse yet; keep vocabularies compatible with `docs/plans/11-evaluation-labeling-and-llm-judge.md` (especially transcript mismatch, boundary, unclear/fast/overlap/noise/named-entity flags) without creating a dependency on absent code.

Predeclare source classes before looking at outcomes. At minimum use source language × caption provenance (`authored`/`automatic`); channel and clip-level acoustic/speech categories are stratified breakdowns and may become separate policy classes only with enough independent videos. Keep channel-level and video-level denominators visible because dozens of segments from three authored videos do not provide dozens of independent source observations. Use distributions (median/IQR/p90 or full quantiles), threshold counts, and per-video summaries, with video-clustered bootstrap intervals if sample size supports them; means alone are inadequate and WER can exceed 100%.

The recommendation vocabulary is fixed by the plan: `use_directly`, `attach_score`, `verify_selectively`, `replace_with_asr`, or `collect_more_evidence`. The report should map every tested predeclared source class to exactly one recommendation, cite its automatic distribution and reviewed error examples, and state the operational consequence. Do not replace authored captions with ASR merely because their punctuation differs, and do not promote automatic captions based only on agreement with an ASR model that may share correlated weaknesses. If video diversity or manual adjudication is insufficient, `collect_more_evidence` is the honest policy.

Useful experiment success criteria are about decision quality rather than a universal WER cutoff: the frozen sample is rerunnable without silent substitution; intended strata and missing strata have denominators; automatic disagreement is separated from human-confirmed caption error; each source class receives an evidence-backed policy or explicit “more evidence” result; and each optional acoustic feature is marked usable/not usable from documented review. A negative result—ASR disagreement not reliably identifying caption errors, or SQUIM not matching human clarity—is successful completion if these criteria are met.

Report invalid/orphan files separately so totals can be reconciled. Legal/provider review is a real gate, not boilerplate. The current YouTube Terms restrict downloading/automated access except as authorized by the service or with prior permission, and the user-facing license for uploaded content is generally limited to use through service features: <https://www.youtube.com/t/terms>. YouTube's API developer policies also prohibit caching audiovisual content without prior written approval for API clients: <https://developers.google.com/youtube/terms/developer-policies>. These sources do not determine whether a particular local research use has a statutory exception, so implementation documentation should require the operator to assess jurisdiction, terms, copyright/license, research/teaching exception, and channel-owner permission rather than claim that “research” automatically permits downloading.

Keep acquisition opt-in, local, minimally retained and prunable; record any provider `license` field but treat absence as unknown, and permit an allowlist of operator-approved videos/channels for the experiment. Never commit or publish downloaded audio, full transcripts, signed URLs or model caches. Publish aggregates and only small necessary excerpts where licensed/defensible, preserve source attribution/IDs, and document takedown/prune procedure. A production/host integration needs separate legal review and must not expose local WAVs for offline playback merely because research tooling generated them.
